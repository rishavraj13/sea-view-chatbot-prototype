VIP also left a dangling `Cite:` in visible text, and the existing brochure summary repeats `DEMO`. These issues were reported without fixes, retry, model switch or fallback. Qwen is the configured candidate, not a production-quality endorsement; this sample does not pass all requested scenarios. No comparison winner against other providers is claimed. ## Reasoning and latency evidence

The old 504s occurred at the shared 20-second deadline with default model thinking and up to three generation steps. Old captures did not record reasoning tokens or per-step latency. Their cause cannot be proven retrospectively. In particular, quota exhaustion explains the diagnosed 429s, not every earlier 504.

Google's [thinking docs](https://ai.google.dev/gemini-api/docs/generate-content/thinking) support budget 0 for Gemini 2.5 Flash/Flash-Lite; this disables thinking. The new live captures report 0 reasoning tokens and roughly 1.5-second handler times, but there is no controlled old/new comparison establishing causation. Keep the existing 20-second request deadline and 30-second route maxDuration.

GOOGLE_THINKING_BUDGET defaults to 0 (integer 0-24576). It applies to exact 2.5 Flash/Flash-Lite IDs. 2.5 Pro cannot disable thinking; its budget is floored at 128. Gemini 3/4 IDs instead receive GOOGLE_THINKING_LEVEL (default low); supported levels vary by model. Other Google model controls are unverified and no unsupported budget is injected.

REASONING_EFFORT defaults to low. Groq GPT-OSS uses low/medium/high (none is clamped to low because none is unsupported); Qwen 3.8 accepts none/low/medium/high. Other Groq models receive no reasoning option. See [Groq reasoning](https://console.groq.com/docs/reasoning). OpenRouter sends the configured effort and enabled flag; actual support is model/backend specific. No reasoning text is included in client metadata.
