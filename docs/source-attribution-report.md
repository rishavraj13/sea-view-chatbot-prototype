# Server-side source attribution — 2026-10-31

## Delivered behavior

The model no longer needs to write URLs. The prompt asks for direct, relevant customer prose without URL/citation labels or context/retrieved/source/section terminology, unasked other-product rules or likely/probably inference. The backend selects structured source parts and trace citations from the pure attributeSources result. Public request, stream, provider and tool-result shapes remain unchanged.

Attribution reuses the existing lexical normalizer, excluding URLs, digit-only tokens, question/function/discourse words and generic package wording. Compare exact retrieved chunk text, without giving title/URL metadata credit. The overlap coefficient is shared distinct content words divided by the smaller answer/chunk word-set size. Require **>=0.5 overlap and >=2 matched words**. Rank by overlap, tie by retrieved order, deduplicate source URL and return at most two chunks. This is lexical evidence, not semantic entailment.

Grounding now needs at least one supporting chunk and the **unchanged** numeric/currency/amount/unit/range property check over the combined retrieved text. Model-written URLs provide no evidence. A model URL outside the retrieved URL set still rejects. Optional allowed URLs/labels are stripped for display with punctuation preserved. Detected failures use the existing refusal or silent prose drop beside media. No mixed execution change, fallback, classifier or extra model generation.

Exact historical replays include the initial URL-free VIP follow-up and the mixed rerun price prose; both now accept and include the VIP source. Rain, cancellation, altitude, VIP and ECO abstention replays pass. Invented price/duration, unrelated words and a fabricated URL fail closed. A known but irrelevant model URL does not select the source. The existing numeric suite remains unchanged. Offline trace/SDK-consumer/history tests verify the same source-part shape and shared pipeline. Historical prose can violate the new style instructions while still passing its deliberately separate lexical/property checks.

## Guarantees, assumptions and limits

Only server-owned retrieved URLs can become structured sources, and each selected chunk meets the documented content-word threshold. Every recognized numeric property occurs in the combined normalized retrieved text. No model URL is required or credited; a foreign model URL rejects. Safe fallback invents no replacement fact.

The check cannot establish semantic entailment, negation, scope, causality, completeness, factual ownership or that every clause is supported. Nonnumeric false statements can share vocabulary; numeric facts can belong to another retrieved chunk/entity. A negated safety-briefing counterexample intentionally demonstrates this in tests. Very terse answers, novel paraphrases and incomplete lexical matches can still refuse. Overlap-based source ordering can favor a smaller supporting chunk and does not promise every source supports every claim. Mixed requests can lose a fact or file part. The system's fail-closed policy is not a guarantee that every generated clause is true.

Assumptions: use shared normalization without changing retrieval scoring/coverage, use the overlap coefficient to handle short and multi-chunk answers, and use the user's approved existing rain turn as the refund-chain first message. The original corpus, request/stream/provider/tool-result shapes, timeouts and history/media execution stay unchanged. The protected uncommitted citation report is untouched. ADR 015 supersedes citation portions of ADRs 011/012; their numeric rules and public shapes remain.
